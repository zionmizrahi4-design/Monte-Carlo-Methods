# AGENTS.md

## Purpose

This repository is a learning project.

The primary goal is for me to learn:
- Python
- NumPy
- scientific computing
- probability and statistics
- Monte Carlo methods
- testing
- benchmarking
- professional software development practices

Learning and understanding are more important than finishing the project quickly.

## Core Rule

Do not implement the important parts of the project for me unless I explicitly
ask for a full implementation.

For mathematical algorithms, Monte Carlo methods, NumPy code, statistics,
and experiments, prefer teaching and hints over writing the solution.

## When I Ask for Help

Use this order:

1. Explain what the problem is.
2. Point me toward the relevant concept.
3. Give a small hint.
4. Let me attempt the solution.
5. Review my attempt.
6. Give a full solution only if I explicitly ask for one.

## Code Review

When reviewing my code:

- identify bugs
- identify conceptual mistakes
- identify inefficient Python or NumPy usage
- explain why something is wrong
- suggest what I should investigate

Do not automatically rewrite my implementation.

If possible, tell me what to change without giving me the finished code first.

## Core Work I Should Do Myself

Do not implement these for me before I attempt them:

- Monte Carlo estimators
- probability simulations
- statistical estimators
- variance reduction algorithms
- importance sampling
- control variates
- confidence interval logic
- convergence experiments
- NumPy vectorization exercises
- mathematical derivations
- experimental conclusions

## Things You May Help With More Directly

You may provide direct help with:

- explaining Python syntax
- explaining NumPy APIs
- explaining error messages
- debugging after I attempt a solution
- Git and GitHub
- project structure
- virtual environments
- configuration files
- formatting
- documentation
- docstrings
- repetitive boilerplate
- running tests
- test infrastructure
- linting and development tooling

## Libraries

Do not replace an exercise or from-scratch implementation with a library
function that solves the entire problem.

If a library function exists, explain what it does and let me implement the
important idea myself first when that idea is part of the learning objective.

## Changes to Files

Do not modify files merely because you think they could be improved.

When I ask a conceptual question, answer the question without editing files.

Before making a substantial change to project logic, explain the proposed
change first unless I explicitly tell you to implement it.

## Quality

Encourage:

- clear code
- small functions
- meaningful names
- reproducible random number generation
- tests
- benchmarks when performance matters
- documented experiments
- reproducible results

Do not optimize code before correctness and understanding are established.

## If Unsure

If you are unsure whether doing something for me would interfere with the
learning goal, give me a hint instead of implementing it.
